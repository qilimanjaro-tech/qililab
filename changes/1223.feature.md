Added a `database_schema` argument to `DatabaseManager` and `get_db_manager` declaring which database the manager is connected to: `"measurements"`, `"autocal"` or `"qaas"`. It can also be set with a `database_schema` key in the `.ini` config section. If both are given and differ, the argument is used and a warning is raised; if neither is given, it defaults to `"measurements"`. The accepted values are available as the `DatabaseSchema` type, exported from `qililab.result`.

`DatabaseManager.load_by_id` and `DatabaseManager.add_fitting` are now the single entry points for every schema: they load from, or store the fitting in, the table of the manager's `database_schema`. `load_by_id` behaves the same for all schemas: an id returns the entry, a list of ids returns a list, and an `IndexError` listing the missing ids is raised if any id does not exist. This changes a few things: `load_calibration_by_id` and `load_experiment_by_id` now raise an `IndexError` for a missing id instead of returning `None`, and for the `"measurements"` schema a list with a single id now returns a one-element list instead of the entry itself, and a list with some missing ids raises instead of returning the ones found. Autocalibration measurements now also get their `result_path` rewritten to the shared base path when the local file does not exist, as the other schemas already did. The module-level `ql.load_by_id` takes a `database_schema` argument. `add_fitting` accepts an optional `path` (mandatory for `"measurements"`) and raises an error for `"qaas"`, which has no fitting columns.

`StreamArray` now uses `db_manager.database_schema` to decide where the measurement is saved: `"measurements"` saves through `add_measurement` and `"autocal"` through `add_autocal_measurement`. A `db_manager` with the `"qaas"` schema raises an error, since `StreamArray` cannot save to it.

`AutocalMeasurement` now lines up with `Measurement`: its `platform_before` column is exposed as the `platform` attribute, and a new read-only `target` property returns the measured qubit as a list (`[qbit_idx]`, or `None` when no qubit was stored), matching `Measurement.target`. The database columns are unchanged.
