`Measurement.add_fitting` now reloads the row by its `measurement_id` and only updates the fitting columns, matching `AutocalMeasurement.add_fitting`. Previously it merged the in-memory instance into the session, so a stale `Measurement` object could overwrite columns changed elsewhere, and a missing row was inserted instead of rejected. It now raises an `IndexError` if the measurement does not exist. The fitting `path` is now optional for the `measurements` schema too: `DatabaseManager.add_fitting(id, parameters=...)` no longer raises, and calling `add_fitting` without a `path` keeps the existing `fitting_path` instead of clearing it.
