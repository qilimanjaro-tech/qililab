`NonLinearCrosstalkMatrix` no longer stores its nonlinear parameters as dense "dict matrices" padded with `None`. `beta_c_matrix` and `non_lin_amp_matrix` are merged into `beta_c_params`, which holds the Bessel term as a single `(beta_c, amplitude)` tuple, and `junction_asym_matrix` becomes `junction_asym_params`. Both stay keyed `[bus_i][bus_j]`, and both are now sparse: a pair is present only where that coupling was set, so a missing entry means no coupling rather than a stored `None`.

Setting a parameter to `None` removes its entry outright, dropping the row once its last pair is gone:

```python
xtalk.set_non_linear_params("flux_0", "flux_2", beta_c=-0.234, amplitude=-0.021)
xtalk.beta_c_params  # {'flux_0': {'flux_2': (-0.234, -0.021)}}

xtalk.set_non_linear_params("flux_0", "flux_2", beta_c=None, amplitude=None)
xtalk.beta_c_params  # {}
```

Adding a bus with `xtalk[bus] = {...}` no longer seeds a `None` entry for every other bus, so the parameter dicts grow with the couplings actually calibrated instead of with the square of the bus count.

Calibration files written with the old layout still load: they are migrated on read and saved back in the new format. A legacy file carrying only part of the old trio of dicts, or a `beta_c` whose amplitude is `null`, is refused rather than loaded with calibrated terms silently dropped. Serialized documents also no longer need an unsafe YAML loader for these parameters; each `(beta_c, amplitude)` pair is written as a plain two-element `list` instead of a `!!python/tuple`.

Code that goes through `set_non_linear_params`, `get_non_linear_flux_terms` or `flux_to_bias` is unaffected. Code that read or wrote the three old attributes directly must be updated.
