A `for_loop` whose step doesn't divide the range now has the same number of points in both directions: the count is rounded down whatever the sign of the step. Descending loops used to round it up, so they now have one point fewer: `start=1, stop=0, step=-0.3` sweeps 1, 0.667, 0.333, 0 instead of 1, 0.75, 0.5, 0.25, 0, like its ascending mirror. In a `parallel`, a loop and its descending mirror now sweep the same points, so the descending one reaches `stop`. This applies to the Qblox and QDAC-II compilers, to crosstalk compensation, and to the loop values saved by `ExperimentExecutor`. `ExperimentExecutor` also no longer saves one loop value fewer than the hardware sweeps when the number of points falls just below an integer in floating point, such as `start=0, stop=0.7, step=0.1` (8 points).
