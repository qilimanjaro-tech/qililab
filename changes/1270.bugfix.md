QPrograms where a QDAC-II triggers the Qblox (`qp.set_trigger(...)` with `qp.wait_trigger()` or `qp.if_trigger()`) no longer hang on the last `wait_trigger` with cluster firmware 2.x. With this firmware, `start_sequencer` in qblox-instruments returns without waiting for a reply from the module, so the QDAC-II's first trigger could arrive before the sequencer was waiting for it. qililab now waits 0.1 s after starting the Qblox sequencers before starting the QDAC-II. This is a temporary fix.
