Fixed `QbloxQCMRF.calibrate_mixers`, `QbloxQRMRF.calibrate_mixers` and `Platform.calibrate_mixers`, which could calibrate the wrong output and silently do nothing. The explicit API passed the sequencer id to the private `_run_mixer_lo_calib`, which expects the LO/output index, so a sequencer whose id differed from its output index calibrated the wrong LO (or an index that does not exist). It now calibrates the LO through the public per-output driver methods picked from the sequencer's output: `out{n}_lo_cal` for the QCM-RF and `out0_in0_lo_cal` for the QRM-RF. The `lo and sidebands` sideband calibration now runs only on the targeted sequencer instead of every sequencer of the module. Omitting `channel_id` now raises a `ValueError` instead of returning without doing anything. The `cal_type` argument now uses the runcard/driver vocabulary (`"off"`, `"lo only"`, `"lo and sidebands"`); the previous `"lo"`/`"lo_and_sidebands"` spellings are still accepted but deprecated.
