Deprecated the functions and flags that selected the database table themselves, since a `DatabaseManager` is connected to a single database, declared with its `database_schema`. They will be removed in a future release and now raise a `FutureWarning`:

- `DatabaseManager.load_calibration_by_id` and `DatabaseManager.load_experiment_by_id`: use `DatabaseManager.load_by_id`.
- `DatabaseManager.add_calibration_fitting`: use `DatabaseManager.add_fitting`.
- The `autocalibration` argument of `StreamArray`: select the database with `DatabaseManager(..., database_schema="autocal")` or `get_db_manager(..., database_schema="autocal")` instead.

Until they are removed they keep working, but only with a manager of the matching schema (`"autocal"` for `load_calibration_by_id`, `add_calibration_fitting` and `autocalibration=True`, `"qaas"` for `load_experiment_by_id`, `"measurements"` for `autocalibration=False`); otherwise they raise a `ValueError`. Code that used an autocalibration database without declaring it must now set `database_schema = autocal` in its `.ini` section or pass `database_schema="autocal"`.

Also deprecated, with a `FutureWarning`: `Measurement.load_old_h5`, use `Measurement.load_h5` instead.

The following were renamed without a deprecation period:

- `AutocalMeasurement.platform_before` is now `AutocalMeasurement.platform` (the column is still `platform_before`), both as attribute and as constructor argument.
- The `qubit_idx` argument of `DatabaseManager.add_autocal_measurement` is now `target`.
