qililab's `QProgram` now runs on the shared [`qprogram`](https://github.com/qilimanjaro-tech/qprogram) libraries: `ql.QProgram` is `qprogram.QProgram` with the `qp.qblox` (qprogram-qblox) and `qp.qdac` (qprogram-qdac) namespaces, plus what qililab adds: `infinite_loop()`, `if_trigger()`, `qp.qblox.play(..., wait_time)`, `qp.qblox.measure_reset()`, `insert_block()`, the `with_*` transforms and `draw()`. It runs the same programs as before, nothing more:

- Loops are `qp.sweep(variable).from_range(start, stop, step)`, and several loops run in lockstep with `|` (`with qp.sweep(a).from_range(...) | qp.sweep(b).from_range(...):`).
- `measure()`, `qp.qblox.acquire()` and `qp.qblox.measure_reset()` return a measurement handle, named `m0`, `m1`, ... in declaration order unless given a `name=`. Their `fields=` argument chooses what they return: the integrated I/Q (`MeasurementField.IQ`, the default) and the thresholded state (`MeasurementField.STATE`).
- `qp.qblox.scope(bus, averaging=True, trigger_level=None)` records the scope trace of the bus's QRM, replacing `save_adc=True`. Its sequencer, trigger mode, trigger level and averaging are set from the program, so the runcard no longer needs any scope setting.
- Every QProgram is validated, when compiled, against the capability profile `qililab-qblox-parity-v1`, which lists what qililab can run. Anything else (a sweep over explicit values on Qblox, a conditional other than `if_trigger`, a variable in a waveform's parameters, arithmetic beyond one `+` or `-`, a QDAC operation inside a loop, ...) raises a `qprogram.ValidationError` naming each problem, instead of compiling to something wrong or being silently dropped.
- `platform.execute_qprogram()` and `platform.execute_qprograms_parallel()` return a `qprogram.QProgramResult`: `result.get(handle)` is an `xarray.DataArray` with one dimension per sweep around the measurement, named after its variable, and an `"IQ"` dimension. `result.get(handle, field="state")` returns the thresholded state, and a scope is a record of its own with the field `"raw"`.
- Programs are stored as `.qp` text (`str(qprogram)`, read back with `ql.QProgram.from_qp()`), in the results database too. Operations and blocks only qililab has are written `qililab.<name>` in a `.qp` file, which then starts with `require qililab 0.1`: the format version of those operations, not qililab's version. Reading such a file with `qprogram.load()` imports qililab by itself. `qp.qblox.disable_autosync = True` is saved too, as a `qililab.disable_autosync` line at the top of the body.
- QPrograms and calibrations saved as YAML by earlier qililab versions still load with `ql.deserialize()`, into the new classes. Runcard gate settings and calibrations keep their YAML waveforms (`!IQDrag {...}`), now read as qprogram waveforms, which have the same parameters and shapes.
- `ql.about()` prints the versions of qprogram, qprogram-qblox and qprogram-qdac.
