The move of `QProgram` onto the `qprogram` libraries fixes these bugs. Programs that ran wrongly without a warning now run as written or raise:

- A numpy number on the left of `+` or `-` with a QProgram variable no longer drops the variable silently. With the former variables, `np.int64(289) - time` gave the number 289 and compiled to a fixed `wait 289`, where `289 - time` gave the expression; both now give the expression. Programs written that way, such as a wait computed from `np.max(...)` of a sweep minus the swept variable, now run the timing they were written for.
- A scope trace is no longer split between the measurements next to it. A QRM records one trace, and with `save_adc=True` on several acquisitions at the same level of a block, each got every n-th sample of it: none of them was the trace. `qp.qblox.scope(bus)` returns the whole trace once, as its own record, and logs that it averages over the acquisitions that triggered it.
- Scoping two buses of one QRM no longer returns the same trace twice: with `save_adc=True` on both, each bus got a copy of the QRM's one trace. Two `qp.qblox.scope()` on buses of one QRM raise a `ValueError`.
- A QDAC `play()` with an `IQPair` raises a `NotImplementedError`, where only its `I` waveform was played.
- A `qp.qdac.*` operation on a Qblox bus raises a `NotImplementedError`, where it was compiled as a Qblox `play` or offset.
- A loop that makes a Qblox wait shorter than 4 ns, the Q1ASM minimum, raises a `ValueError` when the program is compiled: sweep it so that every wait lasts at least 4 ns. Such a loop, a wait sweep from 0 for example, used to run with its start raised to 4 ns, which could drop a point and change the step: `np.linspace(0, 250000, 61)` ran 60 points from 4 ns.
- A non-linear crosstalk compensation of a flux bus set to an expression of a loop variable (`x + 0.05`) raises a `NotImplementedError` naming the bus, where it failed with a bare `StopIteration`: set the bus to the variable itself.
- `Experiment.for_loop()` with a zero or negative step raises a `ValueError` when it is built, where the experiment failed when it ran (`cannot convert float NaN to integer` for a negative step).
