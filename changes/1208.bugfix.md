Fixed deserialization of YAML files (e.g. `QProgram`s and calibration files) that were serialized by qililab versions still depending on `qilisdk`: such files can contain a `!np_scalar` tag that qililab's own YAML loader did not know how to construct, causing a `ConstructorError`. A backward-compatible constructor for `!np_scalar` has been added so these older files load correctly again.

`numpy` scalars are now written as plain python scalars instead, so re-serializing an existing calibration file or qprogram removes the legacy tags over time. The dtype is no longer preserved across a round trip (a `numpy.float32` loads back as a python `float`); the affected values are physical parameters whose dtype is incidental.
