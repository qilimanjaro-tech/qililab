Made `QbloxQCMRF.initial_setup` and `QbloxQRMRF.initial_setup` apply the runcard RF parameters in an explicit, documented order instead of iterating the `parameters` set. Set iteration order over the `str, Enum` members depends on `PYTHONHASHSEED`, so the order in which the LO frequency, the cal-type default and the DC offsets were written changed between processes. This made runcard mixer auto-calibration (`out0_lo_freq_cal_type_default: lo and sidebands`, and the QRM-RF equivalent) non-deterministic: the calibration only ran when the cal-type default happened to be set before the LO frequency, and when it did run the runcard offsets could be written afterwards and overwrite its result. Per output the parameters are now applied as: attenuation, LO enable, the runcard offsets, the cal-type default, then the LO frequency last, so auto-calibration runs on the final configuration and is not overwritten.
