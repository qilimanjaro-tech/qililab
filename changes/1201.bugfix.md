Fixed incorrect Q1ASM emission on Qblox buses when a `wait` or `wait_trigger` immediately followed a pending parameter update (e.g. `set_frequency`, `set_phase`, `set_gain`): the compiler previously always split the flush into a separate `upd_param 4` plus a following `wait`/`wait_trigger`, which undercounted the tracked duration for waits longer than the Q1ASM max. `QbloxCompiler._handle_add_waits` and `_handle_add_trigger_waits` now merge the pending update into the wait itself when it fits in one instruction, track the actual emitted duration for long waits. The flush-and-split lowering for these merged instructions is now handled by `qpysequence`'s `WaitTriggerUpdParam` and the `upd_param` flag on `LongWait`/`LongWaitTrigger`, instead of being computed manually in `QbloxCompiler`.

Concretely, the generated Q1ASM changes shape: where a pending parameter update before a `wait` used to always show up as `upd_param 4` followed by a separate `wait <duration>`, it now shows up as a single `upd_param <duration>` line when the combined duration fits in one instruction.
